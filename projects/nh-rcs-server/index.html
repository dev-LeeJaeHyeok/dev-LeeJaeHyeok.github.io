기술 선택과 구현

TCP 서버에 Netty 프레임워크 기술 선택과 검증

리서치

  • Netty 공식 문서 - 사례를 통해 Netty 기반의 비동기 Non-Blocking 구조가 Connection마다 Thread를 점유하지 않고 소수의 EventLoop Thread로 다수의 연결을 처리하여, Persistent Connection의 유지 비용을 낮출 수 있음을 확인했습니다. 또한 I/O 비중이 높은 환경에서는 실제 운영에서 처리량 증가와 CPU 사용량 감소가 확인된 사례를 바탕으로, 다수의 TCP Session을 지속적으로 유지해야 하는 환경에서 제한된 서버 자원을 효율적으로 활용할 수 있을 것으로 기대했습니다.
  • 운영 사례, 성능 분석 자료 - Netty의 EventLoop 구조가 Thread Migration 감소와 CPU Cache 효율 향상을 통해 요청당 CPU 사용량을 낮추고, 고부하에서 더 높은 처리량과 안정적인 Latency를 보이며, 이를 통해 다수의 TCP Session을 처리하는 서버에서도 제한된 CPU 자원으로 높은 처리 효율을 확보할 수 있을 것으로 판단했습니다.

테스트를 통한 처리량 검증

클라이언트와 서버는 Java 11, Netty 기반으로 개발되었습니다. 실제 로직으로 클라이언트 요청부터 이벤트 발행까지의 처리량과 안정성 검증을 위한 테스트이며, RabbitMQ는 TCP 서버 LAN 환경에 분리 설치하였습니다. 처리 과정은 문자 발송 요청 -> 전문 디코딩 -> Redis SET NX 요청 -> RabbitMQ 이벤트 발행 이며, 10회의 테스트에서 안정적으로 리소스 및 처리량을 유지하는지 확인합니다.

RabbitMQ에 발행되는 이벤트 속도입니다.

RabbitMQ의 안전한 이벤트 처리 로직 구현

접수한 메시지를 유실하지 않으려면, 이벤트 발행에 실패하거나 소비자가 처리 도중 종료되는 상황에 대비해야 했습니다. 고객사에 접수 응답을 보내는 시점과 소비 완료를 알리는 시점을 각각 정했습니다.

  • 접수 응답 : Publisher Confirm으로 브로커 수신을 확인한 뒤 고객사에 응답 전문 전송
  • 소비 완료 : 비즈니스 로직이 완료된 뒤 Manual ACK를 전송해, 처리 중 종료된 메시지는 재전달받도록 구성

Redis를 이용한 중복 요청 검사

중복 요청 : 고객사 식별값과 메시지 식별값을 조합하고, Redis SET NX EX로 동일 요청 여부 검사

중복 검사 Key에는 1시간의 TTL을 적용했습니다. 최대 3,000 TPS가 한 시간 동안 지속되면 최대 1,080만 개의 Key가 유지될 수 있어, 이 조건을 기준으로 Redis 메모리를 계산했습니다.

백엔드 개발

Receiver

고객사에 RCS 문자 전송 요청을 받기위한 TCP서버로 입니다.

  • Netty 프레임워크를 사용하여 전문 타입별 바이너리 처리부터 이벤트 발행 흐름까지 구현
  • 농협측 운영팀과의 기능, 성능, 장애 테스트를 수행하여 기준 통과

Sender

이동통신사에서 제공하는 RCS API를 호출하는 전송 클라이언트 개발

  • 이동 통신사 RCS 처리 RESTful API 연동
  • HTTP 클라이언트에서 발생할 수 있는 모든 예외처리 적용으로 운영기간 장애율 0%
  • 통신사 API 호출 시 연결 실패, 응답 시간 초과 등 HTTP 클라이언트에서 발생할 수 있는 응답을 명확하게 구분하여, 각 상황에 맞는 예외처리를 구현하였습니다.

Reporter

이동 통신사에서 비동기적으로 내려주는 RCS 문자 처리 결과 이벤트를 받아 고객사에게 전달하는 서버입니다.

  • Netty 프레임워크를 사용하여 전문 타입별 바이너리 처리
  • RabbitMQ의 acknowledge mode를 통한 유실없는 이벤트 처리 구현

DB Logger

시스템에서 발생하는 문자 처리 이력과 처리 결과를 반영하는 서버입니다.

  • Database I/O를 위한 JDBC 라이브러리 사용
  • 비동기 환경에서 발생하는 불일치 및 과도한 쿼리 수행을 방지하기위한 Upsert 처리
  • RabbitMQ의 acknowledge mode를 통한 유실없는 이벤트 처리 구현

Storage

문자의 첨부파일을 관리하는 서버입니다. 업로드와 다운로드 API를 제공하며, RCS 문자의 첨부파일을 실제 단말기로 전송하기 위해 이동통신사로 첨부파일 등록 과정을 거칩니다.

  • 이동통신사의 RCS 첨부파일 API 연동
  • JVM Heap 사용량 증가를 방지하기 위한 Buffer 기반 파일 I/O 처리
  • Disk I/O 병목 및 서버 과부하를 방지하기 위한 동시 파일 처리량 제어
  • 비정상 파일 접근을 방지하기 위한 MIME Type 검증
